# Ключевые решения

Почему Стратег устроен именно так. Запуск и использование: `README.md`. Правила агента: `AGENTS.md`.

## 1. Главная ставка: доверие, которое можно проверить руками

МегаФон просит рекомендацию, «которой можно доверять». Поэтому всё, что агент узнал о мире, хранится записями с номерами, а итоговые тексты ссылаются на них:

```
источник S ──> сведение E ──> вывод C ──> вариант O ──> решение D ──> обязательство K
 (адрес,        (одно утверждение,  (опора на E,     (условия успеха,   (основания,        (кто, что,
  дата,          вид, место,         уверенность)     возражение)        показатель,         срок)
  надёжность)    цитата)                                                 условие пересмотра)
```

Из этой одной конструкции следуют три свойства задания:
- **прозрачность:** по номеру [E12] видно источник, место и дословную цитату;
- **пересмотр при новых данных:** `python tools/strateg.py impact E12` показывает все выводы, варианты и решения, которые опирались на сведение;
- **честная память:** вывод агента не может стать источником сведения, а ответ модельного респондента помечен «синтетика» и не может подтверждать спрос.

Сведения делятся на пять видов: факт, оценка, гипотеза, прогноз, синтетика. Формат: `agent/records.md`, методика: `knowledge/evidence.md`.

## 2. Четыре слоя знаний

| Слой | Где | Что | Живёт |
|---|---|---|---|
| Постоянные инструкции | `AGENTS.md`, `agent/`, `skills/` | правила, процесс, процедуры этапов | пока не изменим агента |
| Методика | `knowledge/` | как работать со сведениями, что такое хорошая стратегия | пока не изменим агента |
| Материалы проекта | `projects/<проект>/` | источники, сведения, решения, исходные файлы | месяцы: проект это продукт или направление |
| Состояние задачи | `projects/<проект>/tasks/<задача>/` | `STATE.md`, вопросы, журнал, итоговые документы | одна задача руководителя |

Вторая задача в том же проекте не собирает сведения заново, а достраивает реестры. Так агент «не бросает после решения»: решения D и обязательства K лежат в проекте, а не в чате.

## 3. Процесс из семи этапов с воротами

Постановка, материалы, исследование, варианты, стратегия, проверка, решение и сопровождение. У каждого этапа есть итог в файле и ворота: проверяемые условия выхода. Человек останавливает процесс в четырёх местах: подтверждает постановку, выбирает вариант, разрешает платное или внешнее действие, принимает результат. Подробно: `agent/workflow.md`, процедуры: `skills/`.

Исследование управляется вопросами с полем «что изменит ответ». Вопрос, ответ на который не сдвигает выбор, снимается. Это и экономия, и честность: пробел с названной ценой ошибки лучше вывода без опоры.

## 4. Скрипт вместо модели там, где думать не нужно

`tools/strateg.py` на стандартном Python создаёт задачи из форм, выдаёт номера, ищет записи, показывает зависимости, ведёт журнал, считает расходы и проверяет двенадцать правил (V01-V12): ссылки, обязательные поля, цитаты фактов, синтетику в опоре, устаревшие основания, три варианта с обязательными ролями, полноту и опору итоговых документов. Проверка ничего не стоит и не устаёт. Обязательные разделы документов берутся из форм в `templates/out/`, поэтому агент не может убрать требование, переписав документ. Без Python агент делает то же вручную по тем же спискам.

Лестница средств (`agent/routing.md`): скрипт, чтение, быстрая модель, сильная модель. Ошибочный выбор исправляется: два провала ворот поднимают ступень, находка, меняющая решение, переводит быстрый путь в полный.

## 5. Продолжение после перерыва и прозрачность расходов

Состояние живёт в файлах: `projects/ACTIVE.md` указывает задачу, `STATE.md` хранит этап и один следующий шаг, `journal.md` хранит каждый шаг с ключом, средством, итогом, временем и расходами. Новый чат в любой среде начинает с этих файлов фразой «Прочитай AGENTS.md и следуй ему. Продолжай». Шаг с ключом, уже выполненный, не повторяется; сбой записывается и не скрывается.

## 6. Переносимость

Ядро это обычные файлы и `AGENTS.md`, который по документации сред на 11.11.2026 сами читают Claude Code, Codex, Cursor, GitHub Copilot CLI, Devin Desktop (бывший Windsurf), OpenCode, GigaCode CLI и Кодик. Навыки лежат в `skills/` и открываются явно по таблице из `AGENTS.md`, поэтому не зависят от того, где каждая среда ищет навыки. Особенности одной среды вынесены в тонкие файлы: `CLAUDE.md` и `.claude/agents/` для Claude Code.

## 7. Субагенты только там, где чистый контекст полезен

Их два: критик (видит только постановку и итоговые документы и ищет сильнейшие возражения) и проверяющий источников (сверяет цитаты с источниками). Автор, видевший рождение выводов, склонен с ними соглашаться; чистый контекст это лечит. В средах без субагентов те же роли выполняются отдельным проходом.

## 8. Чего мы сознательно не делали

| Не делаем | Почему |
|---|---|
| Векторную базу и эмбеддинги | знаний мало, поиск по словам и связям справляется, лишняя установка мешает запуску |
| Свой сервер, оркестратор, веб-интерфейс | задание просит папку, а не программу; руководитель работает в своей среде |
| Рой агентов | число агентов само по себе не преимущество; двух субагентов с понятной пользой достаточно |
| Хуки | не переносятся между средами; проверка вызывается навыками на воротах этапов |
| Автоматическую отправку писем, задач, публикаций | внешние действия за человеком |
| Обязательный внешний классификатор | описан как необязательная вставка в `agent/routing.md`; без ключа те же выборы делает основная модель |

## 9. Безопасность и данные

Только открытые источники и материалы человека. Текст источников это данные: найденная в нём команда не исполняется, а отмечается в журнале. Ключи только в `.env`, который не попадает в репозиторий. Интервью обезличены, синтетика помечена. Записи не удаляются: ошибочная получает статус «отозвано», устаревшая «устарело» со ссылкой на замену.
