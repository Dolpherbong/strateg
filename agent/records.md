# Формат записей

Всё, что агент знает и решает, хранится записями семи видов. Запись это заголовок с номером и строки «поле: значение». Формат один для человека, агента и скриптов.

## Общие правила

1. Заголовок: `### E12` или `### O2 Короткое название`. Буква вида и номер.
2. Номера сквозные по проекту и не используются повторно. Следующий номер: `python tools/strateg.py next E`.
3. Поля строками `- поле: значение`. Имена полей писать точно как здесь.
4. Ссылка на запись в свободном тексте: номер в квадратных скобках: [E12], [C3, E15]. Номер без скобок там ссылкой не считается. В полях-ссылках (`источник`, `основание`, `опора`, `выбран вариант`, `основания`, `к решению`, `заменено`) номера пишутся без скобок, через запятую.
5. Записи не удаляются. Меняется поле «статус».
6. Даты пиши как `2026-11-12`. Кварталы пиши словами («4 кв. 2025»), чтобы не путать с номерами вопросов.
7. Записи внутри блоков кода и комментариев скрипты не читают: там можно держать образцы.
8. Обязательны все поля образца, кроме «заметка» у S и «ответ» с «уверенностью» у Q, пока он не закрыт. У E обязательны «текст», «вид», «период», «статус», «задача» и поля своего вида из таблицы ниже. Статусы S и C те же, что у E. Нечего написать: пиши «нет данных», пустое поле проверка считает отсутствующим.

| Вид | Что | Файл |
|---|---|---|
| S | источник | `projects/<проект>/sources.md` |
| E | сведение | `projects/<проект>/evidence.md` |
| Q | вопрос исследования | `tasks/<задача>/questions.md` |
| O | вариант | `tasks/<задача>/out/options.md` |
| C | вывод | `tasks/<задача>/out/situation.md` |
| D | решение | `projects/<проект>/decisions.md` |
| K | обязательство | `projects/<проект>/decisions.md` |

## S: источник

```
### S3
- название: Тарифы на сайте оператора N
- тип: сайт
- где: https://example.ru/tariffs
- дата источника: 2026-11
- дата обращения: 2026-11-12
- надёжность: A
- статус: действует
- заметка: цены для Москвы
```

Тип: `документ`, `таблица`, `сайт`, `интервью`, `изображение`, `аудио`, `видео`, `продукт`, `модель`. Для файлов поле «где» это путь в `inbox/`. Надёжность A, B или C: `knowledge/evidence.md`. Тип `модель` ставится ответам модельных респондентов.

## E: сведение

```
### E12
- текст: Подписка стоит 450 ₽ в месяц для Москвы
- вид: факт
- источник: S3
- место: блок «Подписки», первая карточка
- цитата: «450 ₽/мес»
- период: ноябрь 2026
- статус: действует
- задача: 01-podpiska
```

Вид: `факт`, `оценка`, `гипотеза`, `прогноз`, `синтетика`.

| Вид | Обязательные поля сверх общих |
|---|---|
| факт | источник, место, цитата |
| оценка | основание (номера сведений), расчёт (путь к скрипту или формула) |
| гипотеза | как проверить |
| прогноз | источник или «свой», срок прогноза |
| синтетика | источник типа `модель` |

Статус: `действует`, `устарело` (нужно поле `заменено: E40`), `отозвано` (нужно поле `причина`). Цитата дословная, до 25 слов.

## Q: вопрос исследования

```
### Q4
- вопрос: Готовы ли родители платить за контроль отдельно от тарифа?
- зачем: выбор между O2 и O3
- что изменит ответ: да, тогда отдельная подписка; нет, тогда только в составе тарифа
- где искать: цены конкурентов, отзывы, интервью
- статус: закрыт
- ответ: частично: платят при цене до 200 ₽ [E12, E18]
- уверенность: средняя
```

Статус: `открыт`, `закрыт`, `снят` (не меняет выбор), `пробел` (узнать не удалось; добавить поле `чем грозит`).

## C: вывод

```
### C2
- текст: Отток связан с ценой, а не с качеством приложения
- опора: E12, E18, E21
- уверенность: средняя
- что может опровергнуть: данные об оттоке по версиям приложения
- статус: действует
```

Вывод опирается на сведения и другие выводы. Вывод никогда не становится источником сведения. Уверенность `высокая` или `средняя` требует в опоре хотя бы один факт или оценку. Синтетика в опоре запрещена.

## O: вариант

```
### O1 Оставить как есть
- роль: статус-кво
- суть: ничего не меняем, поддерживаем приложение текущей командой
- что должно быть правдой: отток остановится сам [гипотеза]; расходы не вырастут [E7]
- выгоды: нет новых затрат
- цена и риски: потеря аудитории продолжится [C2]
- возражение: через год продукт придётся закрывать в худших условиях
- ответ на возражение: не закрыто
- чего не знаем: скорость оттока в следующем году
- дешёвая проверка: не нужна
```

Роль: `статус-кво`, `закрыть`, `активный`. В задаче есть по одному варианту первых двух ролей и не меньше одного активного, всего не меньше трёх.

## D: решение

```
### D1
- решение: запускаем отдельную подписку для родителей
- дата: 2026-11-20
- кто решил: руководитель продукта
- выбран вариант: O2
- основания: C2, C4, E12
- отвергнуто: O1: отток продолжится; O3: нет данных о спросе
- ответственный: руководитель продукта
- показатель: доля платящих среди активных, цель 8% к марту 2027
- срок проверки: 2027-03-01
- условие пересмотра: доля ниже 4% через 8 недель или запуск бесплатного аналога у конкурента
- статус: действует
```

Статус: `действует`, `пересмотрено` (нужно поле `заменено: D3`), `отменено`. Людей называть ролями, без личных данных.

## K: обязательство

```
### K1
- что: собрать данные об оттоке по версиям приложения
- кто: аналитик продукта
- срок: 2026-12-01
- к решению: D1
- статус: открыто
```

Статус: `открыто`, `выполнено`, `сорвано`, `снято`.

## Как записи связаны

Источник S даёт сведения E. Сведения отвечают на вопросы Q и держат выводы C. Выводы и сведения обосновывают варианты O и решения D. К решениям привязаны обязательства K. Поэтому по любой фразе результата можно дойти до цитаты, а по любому новому сведению найти всё, что от него зависит: `python tools/strateg.py impact E12`.
