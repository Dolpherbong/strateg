# Инструменты

Один скрипт: `tools/strateg.py`. Он делает то, что машина делает надёжнее и дешевле модели: создаёт папки из форм, выдаёт номера, ищет записи, показывает зависимости, проверяет ворота, ведёт журнал, считает расходы. В сеть не ходит и модели не вызывает. О смысле написанного не судит: это работа навыка `review`.

Состояние на 11.11.2026: этот файл описывает договор, по которому пишется скрипт. Пока скрипта нет, агент работает вручную: `AGENTS.md`, раздел «Инструменты».

## Запуск

```
python tools/strateg.py <команда> [параметры]
```

- Запускай из корня репозитория. В Windows, если команды `python` нет: `py tools/strateg.py ...`.
- Нужен Python 3.10 или новее. Сторонних пакетов нет, установка не нужна.
- Вывод: обычный текст на русском в UTF-8, одна находка на строку.
- Общие параметры: `--root <путь>` (корень репозитория, по умолчанию папка над `tools/`), `--project <имя>` и `--task <имя>` (по умолчанию из `projects/ACTIVE.md`).

| Код завершения | Значение |
|---|---|
| 0 | команда выполнена, нарушений нет |
| 1 | `check` нашёл нарушения |
| 2 | ошибка запуска: неверный параметр, нет файла, нет активной задачи |

## Команды

| Команда | Что делает | Пишет в файлы |
|---|---|---|
| `new project <имя>` | создаёт проект из `templates/project/` | да |
| `new task <проект> <NN-имя>` | создаёт задачу из `templates/task/` и делает её активной | да |
| `status` | где мы: задача, этап, следующий шаг, счётчики, просрочки | нет |
| `next <буква>` | следующий свободный номер записи | нет |
| `find <номер или слова>` | находит записи | нет |
| `impact <номер>` | показывает всё, что опирается на запись | нет |
| `check [--final]` | ворота: проверки V01-V12 | нет |
| `log ...` | дописывает строку в журнал | да |
| `cost` | сводка времени и расходов | нет |

### new project

- Имя: строчные латинские буквы, цифры, дефисы.
- Копирует `templates/project/` в `projects/<имя>/`, заменяет `{{project}}` и `{{date}}`.
- Проект уже есть: отказ, код 2. `projects/ACTIVE.md` не меняется.

### new task

- Копирует `templates/task/` в `projects/<проект>/tasks/<NN-имя>/`, создаёт пустые `work/` и `out/`, заменяет `{{project}}`, `{{task}}`, `{{date}}`.
- Записывает проект и задачу в `projects/ACTIVE.md`.
- Задача уже есть или проекта нет: отказ, код 2.
- Формы итоговых документов не копирует: агент берёт их из `templates/out/` в начале этапа.

### status

Печатает из `STATE.md`: проект, задачу, этап, статус, следующий шаг, чего ждём от человека. Затем по реестрам: число записей по видам и статусам, открытые вопросы, обязательства K с прошедшим сроком и статусом `открыто`, решения D с прошедшим сроком проверки и статусом `действует`. Активной задачи нет: говорит об этом и перечисляет проекты и задачи, код 0.

### next

`next E` печатает следующий свободный номер, например `E13`: наибольший номер этой буквы во всём проекте (все файлы, все задачи, любые статусы) плюс один.

### find

- `find E12`: запись целиком, её файл и строка.
- `find цена подписки`: записи, где есть все слова, без учёта регистра.
- Отборы: `--type E`, `--kind факт`, `--status действует`. Можно без слов: `find --type Q --status открыт`.

Ищет по всему проекту, во всех задачах.

### impact

`impact E12` печатает зависимости по уровням: сначала прямые, затем зависимости зависимостей. Зависимость это запись, которая ссылается на номер, или раздел `## ` документа в `out/`, где есть ссылка на него. Ищет по всему проекту. Нужна для пересмотра: `agent/workflow.md`.

### check

Проверяет реестры проекта и активную задачу. Одно нарушение, одна строка:

```
V03 projects/demo/evidence.md E12: нет цитаты
```

В конце итог: сколько нарушений по каждой проверке. Без `--final` проверяется только то, что уже есть: новая задача из форм проходит с кодом 0. С `--final` (этап 6) добавляются V10 и V11: полнота итоговых документов и опора в них.

### log

```
python tools/strateg.py log "<действие>" --stage <N> --tool <средство> --result "<итог>"
    [--minutes <N>] [--tokens <тыс.>] [--cost <₽>] [--approx] [--key <ключ>] [--status готово|сбой]
```

- Дописывает строку в `journal.md` активной задачи. Номер растёт на один, время ставится само: `ГГГГ-ММ-ДД ЧЧ:ММ`.
- Средство: ступень из `agent/routing.md` (`скрипт`, `чтение`, `быстрая модель`, `сильная модель`) или `субагент`, `классификатор`.
- `--approx` помечает числа как оценку знаком `~`. Статус по умолчанию `готово`.
- Ключ уже есть в журнале со статусом `готово`: скрипт печатает «уже сделано» и эту строку, ничего не пишет, код 0.
- Знак `|` в тексте заменяется на `/`, чтобы не сломать таблицу. `STATE.md` скрипт не трогает: его обновляет агент.

### cost

Сводка по журналу активной задачи: шаги, минуты, тысячи токенов, рубли. Всего, по этапам и по средствам, отдельно число сбоев. Оценки помечены `~`. С параметром `--price <₽ за тыс. токенов>` считает рубли из токенов там, где ячейка «₽» пуста.

## Как скрипт читает файлы

1. Реестры: в проекте `sources.md`, `evidence.md`, `decisions.md`; в задаче `questions.md`, `out/situation.md`, `out/options.md`. Документы: все `out/*.md`.
2. Запись начинается строкой `### <буква><число>` (после номера может идти название) и кончается перед следующим заголовком любого уровня или в конце файла.
3. Поле это строка `- имя: значение`. Делится по первому двоеточию. Имя сравнивается без учёта регистра и пробелов по краям. Значение занимает одну строку.
4. Внутри комментариев `<!-- ... -->` и блоков кода скрипт ничего не читает: ни записей, ни ссылок.
5. Ссылки. В полях-ссылках (`источник`, `основание`, `опора`, `выбран вариант`, `основания`, `к решению`, `заменено`) номера стоят без скобок, через запятую. Слово «свой» в поле «источник» у прогноза ссылкой не считается. В остальных полях и в тексте документов ссылка это номер или список номеров в квадратных скобках: `[E12]`, `[C3, E15]`. Номер без скобок там не ссылка. Другие скобки, например `[гипотеза]`, это пометки.
6. Раздел документа: текст от заголовка `## ` до следующего заголовка `## ` или `# `, вместе с записями внутри.
7. Обязательные поля и допустимые значения описаны в `agent/records.md`. Скрипт держит их одной таблицей в начале файла. Меняешь формат: правь оба места.

## Проверки

| № | Что | Нарушение |
|---|---|---|
| V01 | Номера и места | повтор номера; ссылка на запись, которой нет; запись лежит не в своём файле |
| V02 | Поля | нет обязательного поля; значение не из списка; дата в полях «дата», «дата обращения», «срок», «срок проверки» не в виде `ГГГГ-ММ-ДД` |
| V03 | Факт | нет источника, места или цитаты; цитата длиннее 25 слов |
| V04 | Другие виды сведений | оценка без основания или расчёта; гипотеза без «как проверить»; прогноз без источника или срока прогноза |
| V05 | Круг | сведение опирается на вывод: номер C в поле «источник» или «основание» записи E |
| V06 | Синтетика | синтетика в опоре вывода или в основаниях решения; у синтетики источник не типа `модель`; у факта источник типа `модель` |
| V07 | Устаревшее | действующая запись или итоговый документ ссылается на запись со статусом `устарело` или `отозвано` |
| V08 | Вывод | нет опоры; уверенность `высокая` или `средняя` без факта или оценки в опоре |
| V09 | Варианты | вариантов меньше трёх; нет роли `статус-кво` или `закрыть`; пусто «возражение» или «что должно быть правдой». Без `--final` срабатывает, когда в `out/options.md` есть хотя бы одна запись O |
| V10 | Документы, только `--final` | в `out/` нет документа из `templates/out/`; в документе нет раздела `## ` из формы; раздел пуст (в нём только комментарии) |
| V11 | Опора в документах, только `--final` | в разделе нет ни ссылки, ни слов «гипотеза», «допущение», «не знаем». Не касается разделов, у которых в форме стоит `<!-- без опоры -->` |
| V12 | Состояние | нет `STATE.md` или `journal.md`; в `STATE.md` пусты «этап», «статус» или «следующий шаг»; `ACTIVE.md` указывает на задачу, которой нет |

Список обязательных документов и разделов скрипт берёт из `templates/out/`, а не из своего кода: форма это единственное место, где он задан. Метку `<!-- без опоры -->` он тоже читает из формы, поэтому снять требование правкой документа нельзя.

## Чего скрипт не делает

- Не ходит в сеть и не вызывает модели.
- Не правит и не удаляет записи. Пишут только три команды: `new` создаёт файлы, `new task` переписывает `ACTIVE.md`, `log` дописывает строку журнала.
- Не оценивает смысл: сильное ли возражение, верна ли стратегия. Это навык `review` и человек.
- Не разбирает материалы из `inbox/`: их читает агент.
