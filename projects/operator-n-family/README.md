# Пример по брифу МегаФона: связь для близких и собственных устройств

Главный демонстрационный проект. Задача взята из брифа МегаФона к заданию «Стратег Фабрики продуктов». Оператор вымышленный, все числа брифа учебные. Агент прошёл задачу в Claude Code (модель Opus) 19.11.2026.

## Задача руководителя

Первая реплика, дословно: «Новая задача: пришёл бриф на стратегию продуктового направления, он лежит в файле brief-megafon.md в корне папки. Нужно пройти его целиком и сдать один документ по его форме из пяти частей. Оператор вымышленный, все числа в брифе учебные; открытые данные рынка можно брать для контекста. Решения руководителя по брифу: в конце первого квартала, давать ли людей и деньги на пилот, в конце второго, расширять, менять предложение или наблюдать».

## Что получил агент

- Бриф целиком: `inbox/brief-megafon.md` (текст PDF из кабинета конкурса дословно, таблицы перенесены вручную). Агент записал его источником заказчика: учебные числа брифа это материал заказчика, а не факты о рынке.
- Ответы руководителя в разговоре: подтверждение постановки, «хватит» после исследования, выбор варианта, приёмка, сроки решения, новые данные от владельца системы расчётов.
- Замечания руководителя к расчётам первой и второй версий итогового документа; агент разбирал их как проверку своей работы, а не как источник фактов.

## Где результат

- **Итоговый документ по форме брифа:** `tasks/01-family-devices/out/deliverable.md`, четвёртая версия. Пять частей в порядке брифа, расчёты рядом с решениями, в конце таблица «требование брифа и где оно закрыто». Предыдущие версии: `tasks/01-family-devices/work/archive/`.
- **Решение на одной странице:** `tasks/01-family-devices/out/summary.md`.
- **Рабочие документы:** картина ситуации, пять вариантов с «оставить как есть» и «не развивать», продуктовая и коммуникационная стратегии, план проверки, отчёты о пересмотрах в `tasks/01-family-devices/out/`.
- **Расчёты:** `tasks/01-family-devices/work/calc_*.py` (стандартный Python, без сети), их вывод в `work/calc-outputs-*.txt`.
- **Субагенты:** ответы критика на этапах 4 и 6 в `work/critic-options.md` и `work/critic-review.md`; проверяющий источников сверил цитаты сведений с брифом на этапе 6.
- **Решение:** цепочка D1 → D2 → D3 → D4 в `decisions.md`. Действует D4: сейчас деньги только на работу первого квартала, решение о пилоте сигнала семье 31.03.2027 по заранее записанным условиям; одиннадцать обязательств с ответственными и сроками.

## Как шла работа

16 реплик руководителя, около 59 минут работы агента, около 24 $ по ценам API (работа в рамках подписки). Основной путь от брифа до решения, «Стоп» с продолжением в новом чате, «Где мы?» и пересмотр по новым данным: 12 реплик, около 36 минут. Ещё 4 реплики и около 23 минут ушли на доработку расчётов по замечаниям, итог третья версия. 20.11.2026 ещё 2 реплики и около 6 минут (около 2,6 $): агент свёл условия решения D4 в одну таблицу шагов во всех документах и убрал из сообщений клиенту обещания, которые продукт не гарантирует; это четвёртая версия.

Полный перечень реплик и ответов: `docs/validation/brief-run.md`. Чтобы повторить прогон в чистой копии, положите бриф `inbox/brief-megafon.md` в корень папки или назовите агенту этот путь.

## Как проверить

Из корня репозитория:

```
python tools/strateg.py check --project operator-n-family --task 01-family-devices --final
python tools/strateg.py fragile --project operator-n-family
python projects/operator-n-family/tasks/01-family-devices/work/calc_strategy.py
```

Сохранённые тексты страниц (`.cache/`) в репозиторий не входят. Открытые данные рынка в этой задаче служат только контекстом и на расчёты не влияют.
